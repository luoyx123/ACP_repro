# 5080：23DoF四场景Stage1训练

本次按用户要求在 `hitcsc@192.168.50.27` 的 RTX5080 16GB 上启动 ACP＋SuperMimic Stage1：1024环境、24000轮。保留ACP奖励、随机化、468／353观测、23DoF球手模型，不使用29DoF修复版，也不加入PHP。

## 动作与分配

一个共享actor／critic，按场景固定分配，各256环境；actor没有技能ID，不输入参考关节角。

| 场景组 | 稳定数据ID／片段 | 时间窗口 |
| --- | --- | --- |
| walk | `lafan_asap23`／`walk4_subject1` | 22～28s，沿用既有6s行走窗口 |
| box | `omni_asap23_arm_repair_smooth`／`climb_00_z_scale_0.9` | 0～20.1s，沿用已有肩肘接触修复 |
| climb12 | `omni_asap23`／`climb_12_z_scale_1.0` | 完整0～19.16s |
| climb15 | `omni_asap23`／`climb_15_z_scale_1.0` | 完整0～6.16s |

未指定的地形缩放采用原尺度1.0；climb00保留已用于训练的修复版0.9。12／15仍保留原离线失败项，配置显式记录实验性使用，不宣称数据已通过全部离线准入。初始化仍启用30mm穿透门槛、最多8次重采样；没有放宽。CSI沿用初始相位0.9，随后按实际完成情况向动作前段扩展；尾段完成率不能代表完整动作成功。

选择单独记录于 `configs/stage1_5080_walk_climb.json`，没有改写默认两片段配置。训练超参数仍为 `configs/supermimic.json`：三层2048世界模型、bf16、8步拟合、32步想象、WM批量2048、策略批量1024、UTD=0.4、前500轮仅拟合世界模型。这里的24000轮是SuperMimic更新轮数，不是PPO轮数，也不保证收敛。

## 部署时解决的问题与验证边界

- Torch2.10.0+cu128、MuJoCo3.11.0、MuJoCo-Warp3.11.0、Warp1.14.0；驱动575.57.08，支持5080的sm_120。
- Warp3.11不支持网格对在正margin下启用MULTICCD。保留2mm接触margin，显式关闭MULTICCD；3.11采用disable bit，旧版采用enable bit，代码兼容两者。这改变了多点接触算法，作为引擎差异记录，不能声称与PhysX完全一致。
- TensorBoard2.20需要 `pkg_resources`，独立ACP环境固定 `setuptools<81`；未修改原InstinctMJ项目环境。
- 四场景CUDA冒烟完成，8环境真实采集、468／353观测、参考角度不泄漏给actor、世界模型和策略有限梯度，优化器步数0。该检查不等于正式训练收敛。
- 本次训练指标写入原生TensorBoard事件文件；`progress.json`和`metrics.jsonl`同时保留，以区分TensorBoard服务启动、数据采集和实际优化进度。
- 首次完整规模编译反传发现多场景原地更新normalizer会修改前一场景反传保存的buffer。已改为先采样全部场景并更新统计，再固定统计进行所有场景可微前向；新增 `aot_eager` 多场景反传回归测试。失败尝试归档在 `5080_initial_compile_failure_v1`，未完成任何更新；当前正式目录是修复后重新启动的进程。

启动核验已完成第5轮、50次WM优化，损失1.395、梯度范数3.61、显存约5.9GB，无新增报错；后续进度以远端 `progress.json` 为准。此时尚处于前500轮WM预热阶段，不能称策略已经更新或验证收敛。

最终成功率仍需在训练后分别从动作起点和CSI尾段做物理评估，并查看视频；不能用短冒烟或当前训练奖励替代。
