## 跨机器路径与模型

远端本机配置包含 `path_overrides`：将本机原始数据根路径映射到远端副本；`portable_model_root` 指定可再生模型路径缓存。

```bash
# 远端：标准库即可生成模型路径副本
PYTHONPATH=src python3 -m acp.management.portable
```

这会在 `outputs/缓存/portable_models/` 生成需要改路径的 XML/URDF 副本，仅替换网格／包含文件目录等位置属性。原模型、NPZ、manifest 字节保留不变；JSON 消费者通过统一路径解析器选择当前机器的模型副本。前后 SHA-256 和路径映射写入 `outputs/管理/跨机器模型路径副本.json`。

副本的字节哈希与原模型不同。原报告里的模型哈希仍指向原始证据；重新评估与 M2 物理校准应使用当前实际模型并记录其哈希，不能把迁移视作完成了动力学验证。

## 单卡隔离与退出修复

排查时物理 GPU 1 正运行其他训练任务（约 23GB 显存），GPU 0 主要是桌面进程。这里的物理编号以 `nvidia-smi` 为准；现有训练任务使用了可见设备映射，其命令行 `cuda:0` 实际对应物理 GPU 1，不能只看命令行决定空闲卡。

两个问题需要分别处理：

1. 当前 SimulationApp 默认 `multi_gpu=True`，Headless Kit 也启用了 `renderer.multiGpu.enabled/autoEnable`。指定 `device` 只设置物理／渲染首选卡，并不保证隔离。ACP 按 UUID 设置 `CUDA_VISIBLE_DEVICES`，关闭多卡及自动启用，明确指定物理渲染卡；CUDA／PhysX 使用可见设备内的 `cuda:0`。官方选项说明见 [Isaac Sim SimulationApp](https://docs.isaacsim.omniverse.nvidia.com/5.1.0/py/source/extensions/isaacsim.simulation_app/docs/index.html)。单卡复测未再出现上述 peer-access 错误。
2. 只修正 GPU 后仍停在 `app.close()`。当前 IsaacLab 的 SimulationContext 在 STOP 事件中会进入持续 render 的等待循环，关闭 stage 会触发该事件。ACP 在关闭应用前调用公开接口 `clear_all_callbacks()`、`SimulationContext.clear_instance()`，先解除该回调，再执行正常 `app.close()`。没有修改共享 IsaacLab 源码，也没有通过 `skip_cleanup` 或强行退出掩盖问题。100 步对照测试已以返回码 0 退出。

统一入口会先检查目标 GPU 是否已有计算任务，发现后直接拒绝启动，桌面进程除外。此检查是启动时快照，不是跨项目的 GPU 调度锁；训练机仍需协调卡的使用。远端机器配置补充：

```json
{
  "simulation_python": "/home/hitcsc/miniconda3/envs/isaaclabv2.2/bin/python",
  "simulation_gpu": "GPU-d66ddd90-9263-7bd4-1de9-60d851ac74ac"
}
```

```bash
cd /home/hitcsc/ACP_repro
# 物理 GPU 0；不要照抄其他任务的逻辑 cuda 编号
/home/hitcsc/miniconda3/envs/isaaclabv2.2/bin/python \
  scripts/acp_pipeline.py sim-check --gpu 0 --steps 1000 --timeout 120
```

命令将调用配置中的仿真 Python。日志、实际 GPU 设置、步进数、子进程退出码写入新建的 `outputs/管理/仿真预检/<时间>/`。只有完成全部步进且整个子进程返回 0 才记 `passed=true`，仅出现步进完成标记不算成功。
