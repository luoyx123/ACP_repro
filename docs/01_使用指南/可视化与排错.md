## 交互查看

在 ACP 项目根目录执行。使用已经安装 MuJoCo 的 Holosoma 环境；ACP `.venv` 没有安装 MuJoCo。

```bash
cd /home/lyx/train/ACP_repro
/home/lyx/.holosoma_deps/miniconda3/envs/hsretargeting/bin/python \
  scripts/view_omni_trajectory.py \
  --clip climb_00_z_scale_0.9 --show-source
```

实体模型为目标 23 DoF，青色骨架是源 29 DoF 的 15 个 FK 交互点及连线，保留原始世界坐标。源文件使用 quaternion-first 排列，查看器先转换为 MuJoCo 排列；根姿态使用 SLERP，对齐目标时间戳后再计算 FK。青色骨架不是完整源机器人网格，也不是缺失的人体关节恢复结果。

| 操作 | 功能 |
| --- | --- |
| 空格 | 暂停／继续 |
| 左／右方向键 | 向前／后逐帧，并暂停 |
| J / K | 跳到前／后一个自穿透、环境穿透或速度超限段的起始帧，并暂停 |
| R | 返回开头 |
| C | 开关接触标签标记 |
| D | 开关穿透位置标记 |
| S | 开关源 FK 骨架；启动时须加 `--show-source` |
| `[` / `]` | 减半／加倍播放速度，范围 0.125–4 倍 |
| 鼠标 | MuJoCo 原生相机旋转、缩放、平移 |

绿色为标签对应的机器人部位点，黄色为环境最近表面点，两者以线相连；红色为原生自穿透位置，橙色为原生环境穿透位置。HUD 显示时间、帧号、距离、足底水平速度代理量、接触标签和最深碰撞身体对。标记可能被模型遮挡，可转动相机观察。

默认相机跟随根部，`--fixed-camera` 固定相机目标；`--distance`、`--azimuth`、`--elevation` 调整初始视角。播放直接使用文件时间戳，不把帧率写死为 50 Hz。

## 当前问题与修复顺序

全量结果是 145 条均有待修复项，不等于原始 29 DoF 数据全部不可用。整段零超限的保守验收、模型碰撞定义、语义点映射和求解约束都会影响这个结论。先保留原始数据与当前结果作基线，修复输出写入新的目录，不覆盖全量基线。

### 1. 校准模型与碰撞允许对

先对照源 FK 和目标，核查根坐标、地形高度、左右脚足底／脚尖、手部关键点，以及源 spherehand 与目标手部形状差异。不能把关节附近 collision geometry 的结构重叠全部当作姿态错误，也不能把手穿髋部一并忽略。

给源、目标各自建立经过检查的 allowed-collision matrix，记录排除理由；保留现有原生统计，并另加校准后统计。用中立姿态与明显碰撞姿态验证，确保排除结构重叠后仍能检测手／髋、手／腿、左右肢体等穿透。当前“跨超过两个运动关节”的 nonlocal 分类只是诊断，不能代替这个校准。

### 2. 启用自碰撞约束，并验收真实几何

Holosoma 已有 `SelfCollisionConfig`，但默认 `enable=False`、`pairs=[]`；当前两个入口都没有传入启用配置。应从校准后的身体对生成配置，接入人体与机器人 FK 两条入口。配置默认距离 2 cm 也需根据目标碰撞几何校准，不能机械套用到所有身体对。

`solve_single_iteration` 的环境和自碰撞约束是线性化距离；`iterate` 默认最多 10 次，按代价 `isclose` 停止。求解后的四元数归一化和有限步长可能破坏线性化近似，当前缺少最终非线性几何验收。因此求解器返回不等于得到可用帧。

应在候选姿态 `mj_forward` 后重新计算真实碰撞距离、关节范围和支撑残差；按可行性改善与目标下降接受步长，失败则缩小信赖域／回退重求解。初始姿态可能不可行，需有带松弛的可行性恢复阶段，不能要求每个中间试探点都立即零穿透。当前首帧求解失败时会移除 SOC 信赖域再尝试，这条恢复路径尤其需要最终验收。达不到约束就记录失败帧和残差，不能写成成功参考；也不能简单复制前一帧，造成接触时序和速度问题。

`climb_21_z_scale_1.2` 的约 8.7 cm 穿透需要检查碰撞对是否进入线性化、迭代是否收敛以及最终步是否破坏约束，单纯增大支撑代价不能保证解决。

### 3. 重新定义支撑阶段和脚锁

当前源 stance 只依据脚尖 XY 速度 ≤0.3 m/s，低速摆脚也可能被标成支撑。机器人源轨迹可同时利用足底几何到地形的距离、法向速度、接触面 ID、进入／退出滞回与最短持续时间；这些仍是运动学支撑候选，不是力接触真值。

将每段支撑绑定到对应表面的稳定锚点，区分脚跟／脚尖滚动、跨台阶和离地阶段，约束该表面的切向滑动与法向间隙。现有逐帧 XY 脚锁、地面高度脚锁与支撑软代价不能直接保证这套时序。重新评估接触点切向速度，同时保留现有足底 frame 速度代理量，区分真实滑动与足底滚转引起的点速度。

### 4. 加入速度约束与时序优化

现有求解包含位置限制与平滑代价，但没有逐帧 URDF 关节速度硬界限；145 条中有 23 条触发速度筛选。按真实 `dt` 对最终相邻帧差施加速度界限，并对加速度／根部姿态变化加入约束或代价；有条件时使用短窗口优化，减少单帧追踪导致的跳变。

不要对最终 qpos 直接低通后入库：滤波可能重新产生穿透或破坏支撑。若做平滑，应再投影回碰撞、位置、速度和支撑约束，并重新生成几何标签与未来接触目标。

### 5. 小规模验证后再全量重跑

先固定三个诊断样例：`climb_00_z_scale_0.9`（手／髋自碰撞）、`climb_21_z_scale_1.2`（环境深穿透）、`climb_10_z_scale_1.0`（曾需要放松硬脚锁的恢复路径）。同时保留人体路径与机器人 FK 路径的回归样例，避免只修好一种输入。

每次修改比较失败帧数、真实最大穿透、支撑残差、关节速度、映射误差、帧数完整性和收敛状态，不能只比较“求解是否结束”。代表动作通过后再以新目录处理 145 条，重做标签和全量评估。校准后验收可形成 Stage 1 离线参考候选；Stage 2 hindsight 仍需成功 tracker rollout 与实际接触力事件。

本次验证：ACP 测试 14 项通过、2 项 MuJoCo 测试在 ACP 环境跳过；它们此前已在 Holosoma 环境通过。交互窗口通过 Xvfb 播放验证，PNG 已人工检查，完整 MP4 已编码并用 ffprobe 确认时长、帧数和格式。本次新增查看器与修复分析，尚未实施上述求解器修改。
