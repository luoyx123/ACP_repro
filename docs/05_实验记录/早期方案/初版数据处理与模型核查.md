## 2. 29→23 的处理方式

没有查到 ACP 披露一个专门的“29→23 退火流程”。论文只说明部分已有 G1 重定向数据被复用，没有详细解释如何处理具体自由度差异。因此不能把自行设计的转换称为作者流程。

推荐按输入来源选择路线：

1. **原始人形动作 → 目标 G1 23 DoF**：优先路线。使用同一个实际目标模型直接重定向，避免先拟合到 29 DoF 再投影带来的误差。
2. **OmniRetarget 的 `human_joints` → 目标 G1 23 DoF**：适合作为 Holosoma 方法对照；Omni 数据的人体点和场景几何已配对，适合最快验证重定向器和接触标签接口，但与论文复用原 Omni G1 qpos 的基线要分开记录。
3. **只有 G1 29 DoF qpos → 目标 G1 23 DoF**：已实现源模型 FK 交互关键点 → Holosoma interaction mesh → 目标基座与 23 关节优化，带环境非穿透、限位、时间平滑和支撑代价。按关节名投影只提供 nominal 初值，不直接作为输出。当前版本没有显式姿态朝向任务，朝向保持和自碰撞约束仍需补齐。

上述是早期全身重新拟合路径。当前 LAFAN 已采用同一球手模型上的六腕固定子集，40 条均完成转换与接触标签，不需要原始 BVH；原模型与统一模型的 FK 差异单独报告，详见 [LAFAN_ASAP23.md](../../02_数据集/LAFAN1使用说明.md)。

**ASAP 可借鉴，但不能直接叫作 29→23 退火。** ASAP 的 `g1_29dof_anneal_23dof.xml` 和 YAML 是一个 23 关节模型配置：保留 12 个腿关节、3 个腰关节和每臂肩部 3 关节加肘关节，共 23；腕部 6 个关节被省略。Unitree `g1_23dof_rev_1_0` 则保留腰 yaw、每臂 5 个关节（含 wrist roll），移除 waist roll/pitch 和 wrist pitch/yaw。因此两者 DoF 数相同但关节集合、模型树、link frame 都不相同，ASAP qpos 不能直接喂给旧版 Unitree 目标模型。

ASAP 的 `fit_smpl_motion.py` 从 SMPL 关节位置开始，在其 23 DoF MuJoCo/FK 模型上同时优化关节角、root heading 和 root offset，关节限位后每轮做高斯时间平滑；这是“原人形动作直接拟合 23 DoF”的参考，不是先生成 29 DoF 再逐渐锁掉六个关节。可以借鉴其初始化、FK 拟合、限位与时间平滑结构，但目标模型和对应关节名必须换成本项目锁定的 Unitree rev1.0，并补充本任务需要的环境非穿透及接触保持约束。ACP Stage 2 的 `eta_obs/eta_rew` 是训练时接触来源/奖励切换，与 DoF 转换无关。

## 3. 数据源核查

| 来源 | 实际内容 | 本轮状态 |
| --- | --- | --- |
| [lvhaidong/LAFAN1_Retargeting_Dataset](https://huggingface.co/datasets/lvhaidong/LAFAN1_Retargeting_Dataset) | G1 29 DoF CSV，30Hz；root 顺序 XYZ + XYZW | 本地完整 G1 部分 40 条已转为 ASAP 23 DoF，保留 30Hz 子集并生成 50Hz 接触标签与配对诊断 |
| [Ubisoft 原始 LAFAN1](https://github.com/ubisoft/ubisoft-laforge-animation-dataset) | 人形 BVH，需 FK、单位/坐标处理及重定向 | 可作为直接到 23 DoF 的输入，尚未跑原始 BVH 重定向 |
| [jasongzy/Mixamo](https://huggingface.co/datasets/jasongzy/Mixamo) | FBX 人形角色/骨骼动画，**不是 G1 动作** | 已核查 card/tree；后续需 FBX→世界关键点→G1 重定向；具体技能需另筛选 |
| 本地 OmniRetarget Dataset | `qpos` 29 DoF + 配套模型/地形，30Hz；145 条 robot-terrain 中 112 条另有 `human_joints`，33 条没有 | 145 条离线产物和整体评估已完成；保留 human→23 与 robot-FK→23 两类路径及全部失败/恢复记录 |

本地 OmniRetarget 子集：robot-terrain 145 文件，其中 112 个包含 `human_joints`、33 个没有；robot-object-terrain 148 文件，robot-object 1826 文件。当前只处理**无动态物体的 robot-terrain**。后两者有额外 7 维 object pose，不能静默截成机器人动作丢弃环境交互。

两类机器人的 root 存储顺序不同，不能共用 `qpos[:7]` 的盲拷贝：

```text
OmniRetarget Dataset: [qw,qx,qy,qz,x,y,z, joints29]
LAFAN retarget CSV:   [x,y,z,qx,qy,qz,qw, joints29]
本项目计算规范:       [qw,qx,qy,qz,x,y,z, joints29]
```

这是原 Omni 数据集的 Drake 布局；不能据此假设当前 Holosoma/MuJoCo 的新导出结果也是同一布局。新格式须读其导出器再写 adapter。

LAFAN 下载的 `robot_description/g1/g1_29dof_rev_1_0.urdf` 与本地同名 URDF 并不完全一致：例如踝关节 effort/velocity 为 50/37，本地为 35/30，LiDAR 外参也不同。数据文件、source 模型及 target 模型需分别绑定哈希。

## 4. 重定向基线：使用本地 Holosoma fork

**建议作为需重定向数据的主线。** [OmniRetarget 作者项目页](https://omniretarget.github.io/) 的 Code 链接指向 [amazon-far/holosoma](https://github.com/amazon-far/holosoma)。本机采用用户修改过的 fork：

```text
/home/lyx/train/holosoma
src/holosoma_retargeting/
```

该 checkout 已有 21 DoF Roban 的本地扩展和用户未提交的场景 XML，这些改动均保留。本轮已额外注册 `g1_23dof_rev_1_0` 并生成专用模型和 mappings；现有 `g1` 仍是原 G1 29 DoF，T1 是 23 DoF，Roban 是 21 DoF。运行目标配置时必须用 `--robot g1_23dof_rev_1_0`，不能把 `--robot g1` 当作目标 23 DoF。

论文补充表 S1 将 OmniRetarget 的 box-climbing 归为“本文未重定向、本文做了 contact labeling”；LAFAN 与 Mixamo 动作则是“本文重定向并标注”。所以复现时应保留两个可比较的数据路径：**(A) 论文基线**读取 Omni 已提供的 G1 `qpos`，在明确的 source/target 模型间投影到目标 23 DoF，再复现接触标注；**(B) Holosoma 方法对照**读取同一条样本的 `human_joints`，经本地 fork 直接重定向到目标 23 DoF，再用同一个标注器处理。B 更适合验证重定向器，不应替代 A 后仍声称复现了作者的 Omni 数据处理。

其 `InteractionMeshRetargeter` 是 interaction-mesh/Laplacian deformation 加约束 diffIK/SQP 风格优化，已有非穿透、足底保持、关节限位和 trust region 等机制。[原生使用说明](https://github.com/amazon-far/holosoma/blob/main/src/holosoma_retargeting/README.md) 覆盖 LAFAN 与 climbing。相比本项目自写的 Drake 关键点 IK，它是已有的、针对人体-环境交互重定向的开源实现，作为需重定向数据的主线更稳妥；但仍需验证其输出的 G1 23 DoF 运动与 ACP 的 contact body/地形坐标契约一致。

原生重定向输入为世界关键点 `[T,J,3]`。本地 fork 已有 `omniretarget_terrain` 数据格式入口：读取 `human_joints`，按 53 点 mocap skeleton 映射，不直接使用样本内的 29 DoF `qpos`。因此带 `human_joints` 的 Omni 片段可用于路径 B 对照。原始 LAFAN BVH 可通过 FK 得到关键点；Mixamo 则要先将 FBX 骨架映射为受支持的关键点集合。当前按用户选择，已重定向的 G1-29 轨迹优先做按关节名的 ASAP 子集，再根据源／目标接触差异局部修正，避免全身重新拟合破坏已有动作。

本轮目标 `g1_23dof_rev_1_0` 适配状态：

- 已单独注册 robot type，绑定 Unitree URDF/MJCF，固定关节顺序、限位、foot sticking links 和 MuJoCo qpos 输出格式。
- 已新增 53 点 human mapping 及 LAFAN/SMPL mappings，所有目标 frame 存在于生成的 rev1.0 模型，并测试 URDF/MJCF 在非零关节姿态下的 FK 一致性。
- 已为足底/手部增加明确的语义 frame，九部位标签仍为工程映射；未来训练模型需使用同一份 frame/offset 契约。
- 地形配准、环境距离和关节限位已交叉验证；已修正支撑代价共享状态错误，支撑贴合大幅改善。剩余悬空/脚滑、自碰撞和动态执行仍待后续验收。

Drake 原型只保留为几何/格式对照和调试工具，不用它作为论文重定向流程的默认实现，也不把它当前 67.5% 收敛的片段纳入正式训练数据。

## 5. 已实现的最小离线处理

模块：

- `acp.data.motions`：Omni / LAFAN CSV 读取，明确 root 顺序，四元数 SLERP、线性位移/关节插值，30→50Hz，不延长片段。
- `acp.data.scene`：Drake FK、配准地形、robot-environment signed distance；STL 转换为本地缓存 OBJ，不改原模型文件。
- `acp.data.prepare_omni`：按关节名构造删除列基线，再优化 23 DoF 和浮动基座；身体位置/torso 姿态/nominal/时间平滑成本；关节限位、单位四元数、环境非穿透约束。保存全部约束通过标记，并区分求解器收敛状态。
- `acp.data.contacts`：过滤短接触段、竖直力阈值接口、下一 onset、查询时刻 yaw 坐标变换、footprint mask、末尾窗口标记。

离线几何接触使用距离≤1.5cm、最小连续 10 帧；1.5cm 是**工程阈值**，不是论文披露参数。环境穿透容忍为 3mm。几何标签使用环境表面的 witness point；同时保存身体 landmark，避免把两者混作一个字段。手掌 landmark 目前为工程选择，未完成实机或视觉校准。

未来接触：75 控制步、1.5s，包含查询时刻自身的 onset；持续接触不当作新的 onset。窗口不足时保留可见未来事件，但标记 `future_complete=false`。旧 Drake 原型用 `supervision_valid` 同时屏蔽未收敛帧；Holosoma 没有逐帧收敛诊断，新 adapter 只导出 `geometry_window_valid` 等明确范围的掩码，不能把它当作训练质量保证。训练 loader 还需独立接触/动作质量筛选。所有输出仍是 provisional。

此前 Drake 29→23 原型在 1006 帧、50Hz 样例上的硬约束可行比例为 100%，优化器收敛比例 67.5%，身体 landmark 平均误差约 1.41cm（直接删除 6 列对照约 4.10cm），最低环境 signed distance 约 -3.06mm。该结果只作为对照记录，不是 Holosoma 结果，也不达到正式入库标准。Holosoma 对真实 23 DoF 模型的适配及 33 条无 `human_joints` 样本的机器人间迁移均已完成，质量问题见全量报告。

**边界**：几何接触不证明有支撑力；已检查关节速度限位，但没有动力学回放、执行器力矩验证、自碰撞验证或成功 rollout。后续 Stage 2 的 hindsight 必须来自成功执行轨迹，并调用世界系接触力接口提取 >1N 的实际事件。只 replay 运动学状态再读静态求解的接触力也不能代替真实执行。

Drake 对 mesh 距离使用凸包；复杂凹地形必须检查是否有凸包填缝。当前地面为覆盖 [-100,100]m 的 box 顶面 z=0。正式流程要增加模型碰撞分解/校验和对原生 MuJoCo/Isaac 碰撞结果的交叉验证。

## 7. 下一步验收

robot-terrain 145 条及 LAFAN G1 40 条均已完成关节子集、标签与配对诊断；Omni 的三个完整样例还验证了肩肘局部修正。接下来扩展局部接触修正，校准碰撞允许对与足底定义，再扩展 Mixamo。完成以下条件后才把对应动作标成 Stage 1 离线参考候选：
