整个 20.1 s 爬箱参考窗口中，关节速度／配置上限的最大比值约 0.481；关节加速度绝对值 P99 约 44.12 rad/s²、最大约 215.86 rad/s²。这只是运动学检查，**不是力矩可实现性、PD 可跟踪性或动态平衡的证明**。旧 NPZ 未保存动作、PD 目标和力矩，不能据此补造饱和曲线。

## 四组冻结 checkpoint 物理诊断

| 条件目录 | 物理参数 | 延迟 | 控制器 | 回答的问题 |
| --- | --- | --- | --- | --- |
| `nominal_policy` | 名义质量、CoM、PD、armature、零位 | 0 | 已训练策略，确定性动作 | 去掉随机物理后是否仍然在相同阶段失败 |
| `randomized_policy` | Table S2 新采样实例 | 原采样值 | 同一策略 | 随机物理条件下的表现与饱和 |
| `randomized-zero-delay_policy` | 与上一组同 seed、同环境数，逐项核对相同物理样本 | 仅改为 0 | 同一策略 | 将动作延迟与其余动力学影响分开 |
| `nominal_reference_pd` | 名义参数 | 0 | 下一控制步参考关节角直接作 PD 目标 | 检查当前执行器对关节参考的跟踪现象 |

所有组均关闭 actor 观测噪声、里程计误差与初态扰动；从历史 provenance 读取 robot／task 配置，加载同一个 `latest.pt`，不加载优化器、不更新观测归一化。结束后逐张量核对模型未改变，并核对 checkpoint 文件哈希未改变。

名义组使用地面／机器人摩擦 1.0，这是明确记录的工程名义值，不能宣称作者公布了相同机器人名义材质。特别防止关闭随机化后退回 `m2.json` 的旧地面摩擦 0.8。名义 PD 保留历史训练的腿部 kp=400、kd=10；关闭的是比例扰动，不是随意换一套增益。

参考 PD 重放不是学习策略，不能注入根位姿或外力；重放失败不能单独证明动作不可实现。名义组多个环境也不是独立随机样本。随机组是新的物理实例，不能与历史 1,024 个环境逐一配对。

## 采集内容与时间约定

- 50 Hz：策略原始／归一化观测、动作、实际根状态／关节角和速度、身体位置、参考状态、奖励各项、根／姿态误差与四子步接触力。
- 200 Hz：**同一物理步执行之前**的 PD target、q、q̇、computed torque、applied torque。先 `write_data_to_sim` 计算显式 PD，再复制这些量，然后推进物理；避免拿下一步状态验算上一步力矩。
- 静态元数据：真实 kp/kd、力矩上限、关节零位偏置、实际延迟 ticks、身体名称、环境编号及物理参数回读。
- 全环境限幅比例只累计 episode 仍 alive 的子步，包含终止当步；已经失败、继续随仿真步进的环境不再混入统计。
- 报告核对 `τ_computed = kp·(target−q) − kd·q̇` 及 applied 的限幅关系；分别展示失稳前的限幅、关节误差、动作幅度和观测归一化裁剪。不能用失稳后的冲击／饱和反推最初原因。

`G1ReferenceEnv` 的诊断记录缺省关闭；原训练默认评估仍保留从头／尾段两种入口。新增的是显式诊断选项，不改奖励、PPO 或 CSI。

## 运行方式

在仓库根目录执行；本地绘图使用带 MuJoCo／Matplotlib 的 Holosoma Python，远端实际仿真由机器配置中的 Isaac Lab Python 启动。

```bash
# 本地：分析已有回放，不执行物理仿真
/home/lyx/.holosoma_deps/miniconda3/envs/hsretargeting/bin/python \
  scripts/acp_pipeline.py diagnose offline \
  --run outputs/实验归档/stage1/walk_box/20261030_2048env_10000iter_table_s2_v1 \
  --output outputs/实验归档/stage1/diagnostics/20261103_control/offline

# 远端：四组短诊断，GPU0有计算任务时只轮询；每组开始前最多等24小时
.venv/bin/python scripts/acp_pipeline.py diagnose suite \
  --run outputs/实验归档/stage1/walk_box/20261030_2048env_10000iter_table_s2_v1 \
  --output outputs/实验归档/stage1/diagnostics/20261103_control \
  --gpu 0 --num-envs 128 --phases 0 0.24 0.30 0.90 \
  --wait-for-gpu --wait-timeout 86400 --background

# 已有结果：重新汇总图表及实际执行／参考对照视频
/home/lyx/.holosoma_deps/miniconda3/envs/hsretargeting/bin/python \
  scripts/acp_pipeline.py diagnose report \
  --run outputs/实验归档/stage1/walk_box/20261030_2048env_10000iter_table_s2_v1 \
  --output outputs/实验归档/stage1/diagnostics/20261103_control
```

单组使用 `diagnose rollout --physics nominal/randomized/randomized-zero-delay --controller policy/reference_pd`；指定新的 `--output`，不覆盖旧诊断。`--num-envs 128` 是评估规模，不是 128 环境重新训练；walk／box 各 64 环境，全部四组 optimizer steps=0。

## 队列与产物

远端 GPU0、GPU1 在本次初查均有高负载任务。队列只对 GPU0 检查空闲，不创建等待期间的 CUDA 上下文，不结束已有任务；启动实际仿真前再次检查 GPU。执行源码固定在独立 detached worktree，队列的 cwd、提交号、PID、完整参数保存在 `queue.json`，避免等待期间主仓库更新改变已安排诊断。
