# 快速开始

所有命令在项目根目录执行。首选统一入口 `scripts/acp_pipeline.py`，它负责读取机器路径、选择 Python 环境和解析稳定批次 ID；底层脚本仍可直接调用。

## 1. 配置和检查环境

本机已配置；换机器时复制示例并填写实际路径：

```bash
cp configs/machine.example.json configs/machine.local.json
.venv/bin/python scripts/acp_pipeline.py doctor
.venv/bin/python scripts/acp_pipeline.py list
```

`retarget_python` 指向安装了用户 Holosoma 分支、MuJoCo、CVXPY 的 Python；`label_python` 指向本项目安装了 Drake 的 Python。不要把 Python 可执行文件软链接解析到系统解释器，否则可能丢失 Conda/venv 环境。

已有可用环境时，ACP 标注环境可按以下方式新建；版本以 `pyproject.toml` 为准：

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -e '.[dev]'
```

Holosoma 需要本项目使用的修改版本，不能任意替换成上游默认版本；安装和移交细节见 [资产规范](../03_方法与规范/资产与版本管理规范.md)。当前代码保存在独立的 Holosoma 仓库中，运行记录登记其路径，移交应一并保存修改。

可指定另一份机器配置：

```bash
.venv/bin/python scripts/acp_pipeline.py --config /绝对路径/lab_machine.json doctor
```

## 2. 查看进度和目录

```bash
.venv/bin/python scripts/acp_pipeline.py status omni
.venv/bin/python scripts/acp_pipeline.py status lafan1
.venv/bin/python scripts/acp_pipeline.py status mixamo
.venv/bin/python scripts/acp_pipeline.py status php
.venv/bin/python scripts/acp_pipeline.py catalog
```

`clip_statuses` 来自当前 manifest；`quality_summary.json` 是最近一次完整评估快照，长任务运行时两者更新时间可能不同。Mixamo 更细的统计可用：

```bash
.venv/bin/python scripts/acp_pipeline.py status mixamo
```

## 3. 启动／恢复批量处理

先用 `--dry-run` 查看实际命令；去掉后执行。再次运行会检查各数据集自己的内容指纹，复用符合条件的已完成片段；代码、模型或参数改变可能触发重算。主批次仍运行时，统一入口拒绝重复启动。

```bash
.venv/bin/python scripts/acp_pipeline.py run omni --workers 4 --dry-run
.venv/bin/python scripts/acp_pipeline.py run lafan1 --workers 4 --dry-run
.venv/bin/python scripts/acp_pipeline.py run mixamo --workers 8 --dry-run
.venv/bin/python scripts/acp_pipeline.py run php --workers 4 --dry-run

# 示例：PHP 全量，默认每条动作处理地形变体 0
.venv/bin/python scripts/acp_pipeline.py run php --workers 4 --background
```

统一入口默认给每条 Drake 标注子进程 120 秒限时，超时记为处理失败并继续队列；可用 `--label-timeout 300` 调整。该资源限制不改变姿态或接触算法，底层直接调用可通过 `src/acp/pipeline/label_python_bounded.sh` 指定标注解释器包装。

`--background` 记录 `batch.pid`、时间命名日志和 `launches/*.json`。PID 文件是启动记录，是否仍运行可用 `ps -p <PID> -o pid,etime,args` 核对。执行器会限制 BLAS 内部线程，避免多个 worker 相互争抢；当前任务为 CPU 几何与优化，不要求训练 GPU。

**试运行必须指定独立输出目录**，防止将主批次清单改成少量样例：

```bash
.venv/bin/python scripts/acp_pipeline.py run php \
  --clips php_climb_14ae61dde74c_v00 php_locomotion_b204a8ca16dc_v00 \
  --output outputs/实验归档/php/my_pilot --workers 2
```

PHP 可 `--audit-only` 仅清点，或 `--all-variants` 处理全部变体。全变体实验使用新批次目录，避免和单变体基线混淆：

```bash
.venv/bin/python scripts/acp_pipeline.py run php --all-variants \
  --output outputs/数据集/php/all_variants_v1 --workers 4 --background
```

新批次生成后，在 `configs/assets_registry.json` 的 `runs` 登记稳定 ID；先观察样例质量，再决定是否全量生成额外变体。

## 4. 回放和导出

四类数据共用回放器，必须明确选择数据集／批次。同名 clip 可能存在于多个版本，指定固定批次路径可以比较修复前后。

```bash
.venv/bin/python scripts/acp_pipeline.py view omni --clip climb_00_z_scale_0.9 --show-source
.venv/bin/python scripts/acp_pipeline.py view lafan1
.venv/bin/python scripts/acp_pipeline.py view mixamo
.venv/bin/python scripts/acp_pipeline.py view php
```

后三条先列出当前已索引 ID，再加 `--clip <ID> --show-source` 播放。旧命令 `scripts/view_omni_trajectory.py --clip ...` 保留兼容，默认只选 Omni；其他来源需 `--run <批次目录>`。未生成 motion 的失败／待处理动作无法播放；`needs_repair` 动作可以播放用于排错。

2026-10-30 重构后核验快照：Omni 145、LAFAN1 40、Mixamo 1,479、PHP 135 条的播放字段和源叠加文件通过检查。Mixamo 继续处理，数量会增加；PHP 另 5 条缺少已完成标注产物。四类数据各实际渲染了一张叠加 PNG，完整检查不等于逐帧观看全部动作。

```bash
.venv/bin/python scripts/acp_pipeline.py check --manifests --playback
```


不指定 clip 会列出索引；选一个实际 ID 再回放：

```bash
.venv/bin/python scripts/acp_pipeline.py view php
.venv/bin/python scripts/acp_pipeline.py view php \
  --clip php_climb_14ae61dde74c_v00 --show-source
```

服务器无显示器时用 EGL 导出；输出统一放在可视化目录：

```bash
MUJOCO_GL=egl .venv/bin/python scripts/acp_pipeline.py view php \
  --clip php_climb_14ae61dde74c_v00 --show-source \
  --output outputs/可视化/php/climb_example.mp4 --seconds 8

MUJOCO_GL=egl .venv/bin/python scripts/acp_pipeline.py view php \
  --clip php_climb_14ae61dde74c_v00 --seek worst-environment \
  --output outputs/可视化/php/worst_environment.png
```

`--seconds`、`--seek` 等参数透传底层回放脚本。PNG 定格与 MP4 编码由已有工具完成；[回放说明](可视化与排错.md) 列出完整控件。批量任务通常在完整评估后生成回放索引，尚未生成索引时先等评估结束。

## 5. 全量评估与查看失败项

```bash
.venv/bin/python scripts/acp_pipeline.py evaluate omni --workers 4
.venv/bin/python scripts/acp_pipeline.py evaluate php --workers 4
```

在对应批次查看：

- `QUALITY.md`：汇总与每条动作的失败原因。
- `quality_all_clips.csv`：可筛选的总表，分母包含未处理和失败输入。
- `stage1_candidate_clips.txt`：离线运动学候选清单。
- `needs_repair_clips.txt`、`processing_failed_clips.txt`：修正或工程故障队列。
- `clips/<id>/comparison/report.json`：29→23 的保留链误差、手接触变化和新增／继承穿透；Mixamo 原始人体路径不使用此机器人对比。

离线候选不等于仿真训练已经验证。当前标签基于几何距离，后续 Stage 2 的接触力 hindsight 需从实际 rollout 获取。

## 6. 定期核验资产

```bash
.venv/bin/python scripts/acp_pipeline.py check --manifests
```

检查文档本地链接、顶层输出分类、登记目录，以及已完成片段中关键路径能否解析。此检查只读，不替代几何质量评估。

按功能查代码请看 [仓库文件与架构查询](../03_方法与规范/仓库文件与架构查询.md)。每完成一个代码／目录／接口阶段，执行：

```bash
.venv/bin/python scripts/acp_pipeline.py structure --stage "本阶段完成内容"
```
