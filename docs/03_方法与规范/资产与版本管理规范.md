# 资产与版本管理规范

本规范管理可复用算法、数据产物、历史实验和来源证据。项目以 `configs/assets_registry.json` 作为资产登记表，`configs/machine.local.json` 管理本机资源路径，原始数据集保持在项目外部。

## 一、目录职责

```text
ACP_repro/
├── configs/
│   ├── assets_registry.json      # 可移交：稳定 ID、数据集入口、旧→新路径映射
│   ├── machine.example.json      # 可移交：机器资源配置模板
│   ├── machine.local.json        # 本机：Python、仓库、数据集实际位置
│   └── *.json                    # 质量、碰撞校准、语义与场景假设
├── src/acp/data/                  # 共用适配、时间轴、几何与标签实现
├── scripts/                      # 批处理、诊断和统一资产入口
├── tests/                        # 格式、时间、标签和几何回归
├── docs/
│   ├── 01_使用指南/              # 主手册、速查、可视化、图示
│   ├── 02_数据集/                # 每来源的适配与验证说明
│   ├── 03_方法与规范/            # 稳定契约、治理和修正规则
│   ├── 04_论文与复现/            # 论文原件、抽取记录和复现路线
│   └── 05_实验记录/              # 历史方案、阶段结论、报告快照
└── outputs/
    ├── 数据集/<dataset>/<run>/   # 登记后的基线或候选批次，不代表已训练准入
    ├── 缓存/<dataset或用途>/     # 可从原始输入再生的抽取／网格缓存
    ├── 实验归档/<dataset>/<run>/ # 探索、失败方案、回归样例、消融结果
    ├── 可视化/<dataset或主题>/   # MP4、PNG、人工审查材料
    └── 管理/                    # 目录快照、迁移记录、启动资源配置、文档备份
```

顶层不再用 `outputs/test_v2` 等无来源目录。试验进入 `实验归档/<dataset>/`；可以长期保留和比较的主批次进入 `数据集/<dataset>/`。历史报告的英文机器字段保持稳定，人工入口、分类和说明采用中文。

## 二、批次与片段命名

新增批次建议 `<YYYYMMDD>_<method>_vN`，例如 `20261030_asap23_v1`。已有 `asap23_baseline` 保留名称用于追溯。稳定 ID 与物理路径分离：`php_asap23` 可以解析到登记的当前批次，显式路径用于固定实验复现。

主批次算法或场景发生实质变化时开新版本，登记新 ID；`datasets.<name>.run_id` 指向该来源当前入口。一次试跑应显式传 `--output outputs/实验归档/...`，不要复用主批次目录后只处理少量 clip。

片段 ID 尽量保留源标识；PHP 原始文件名过长，使用类别、源相对路径哈希和变体号构造稳定短 ID。完整原名仍存 inventory。文件夹名称可读不代表输入已去重，内容哈希才是复查依据。

## 三、来源与处理记录

每个批次至少保留：输入清单、原始文件内容哈希、模型与地形来源、关节名称、采样率、参数、代码版本／哈希、逐阶段状态、失败原因、质量标准版本。统一入口另存实际命令、本机路径配置、启动时间和后台 PID。

外部 Holosoma 有本项目所需修改：23DoF 配置、可选支撑目标代价、碰撞与数值处理等。移交时应保存以下证据，而不仅是仓库地址：

```bash
# 用你的实际仓库路径；本机见 machine.local.json
# 在独立的交接目录保存，避免覆盖原始工作区
git -C /path/to/holosoma rev-parse HEAD
git -C /path/to/holosoma diff HEAD --binary > /path/to/handover/holosoma.patch
git -C /path/to/holosoma ls-files --others --exclude-standard
```

`git diff` 不包含未跟踪文件；需结合清单一并移交配置／代码。本次整理的 [依赖与来源快照](../../outputs/管理/环境与外部仓库快照.json) 记录版本和状态；外部修改备份在同一管理目录。原始训练数据不随代码补丁打包。

## 四、质量状态与准入

“文件生成完成”只表示数据阶段成功。“离线运动学候选”表示通过当前工程门槛；真实场景确认和训练用途审核另行记录。Stage 2 hindsight 必须来自后续成功 rollout 与接触力事件，不能因有几何标签就登记为完成。

资产登记的 `training_admitted: false` 是项目级当前状态；下游不能只看目录名“数据集”。每条 `quality/report.json` 和批次总表保留通过与失败原因。

Mixamo 椅子／梯子是为验证算法建立的场景假设，`approved_for_training:false`。更新场景需要记录尺寸来源、确认人／依据、版本和新质量报告；默认平地动作也需区分原始场景是否已知。PHP 的十个变体按实际配套文件标记，变体 0 不自动等于无扰动原场景。

## 五、训练／验证划分

先按原始动作分组，再切窗口或分配地形变体，防止同一动作泄漏：

- Omni：同基础动作的五个高度变体属于同一组。
- PHP：同 `*_motion.npz` 的十个地形变体属于同一 `motion_group`，不能跨训练／验证。
- Mixamo：候选名称不能用于证明不同动作；需要源内容／骨架近重复检查，再分组。静态 T/A pose 和角色文件不混入动画训练分母。
- LAFAN1：按实验目的选择 subject 或原始片段分组，不能随机混合同一动作切出的窗口。当前 `motion_group` 可作初始索引，正式发布划分应显式保存 subject 与片段级清单。

同一源动作的基线、局部修正版和增广版本必须保留组关联。任何裁剪、重采样、平移、模型替换都保存派生关系。

## 六、缓存、归档与清理

| 类别 | 保留建议 | 清理前必须确认 |
| --- | --- | --- |
| 外部原始数据 | 保持只读来源 | 不由本项目清理 |
| 数据集批次 | 保留可追溯版本与质量报告 | 下游实验已固定批次与哈希 |
| FBX 骨架缓存 | 优先保留，重抽取成本较高 | 原 FBX 和抽取版本仍在 |
| 网格转换缓存 | 可再生 | 当前无任务正在使用／写入 |
| 历史实验 | 基线、关键失败例和回归视频长期保存 | 原因记录与替代资产已确认 |
| 日志／临时文件 | 按实验室保留期管理 | 无活动进程，失败诊断已留档 |

当前整理只分类移动并留存证据，没有自动删除历史产物。`catalog` 只更新登记资产的状态／体积快照，不会删除文件，也不会自动训练准入。管理目录中的迁移日志和文档备份不计入某个算法运行的体积。

## 七、路径迁移与跨机器使用

本次迁移记录保存在 `outputs/管理/迁移记录_*.json`，文档原版有 tar.gz 备份。旧项目路径和最长前缀重定位映射写入登记表；消费历史 JSON 时使用 `acp.data.assets.read_record`，保存原记录不变。

迁移到另一台机器：

1. 复制代码、configs、docs、登记的必要批次和缓存，保留登记表中的 `original_project_root` 用于识别历史路径。
2. 安装 ACP 与用户修改版 Holosoma 环境，填写新的 `machine.local.json`，执行 `doctor`。
3. 原始数据与外部模型路径发生变化时，**重新生成模型／场景与必要派生结果**。历史 XML/URDF 内的绝对网格路径不是 JSON 解析器可以自动修复的；仅复制 NPZ 不构成可回放资产。
4. 在新批次目录先转换样例并导出 PNG/MP4，完成模型和地形核验后处理全量。
5. 运行 `catalog`，保存交接时的目录清单、环境和代码版本。实验报告引用固定批次与内容哈希，不只引用“当前默认数据集”。

不要为了消除路径报错直接批量改写历史 JSON 或模型，再继续声称原哈希有效。确需迁移模型时，写新资产并记录原模型、新模型和转换关系。

## 八、维护文档

主手册写稳定行为，数据集页写来源差异，实验记录写具体日期与结论；生成报告保留在 outputs，docs 只保存明确命名的阶段快照。新增文档必须进入对应分类并更新 `docs/README.md`。方法变化先更新契约／配置，再把验证结果写入实验记录。

图示使用 `docs/01_使用指南/图示/数据处理流程.dot` 维护，执行 `dot -Tsvg ... -o ...` 生成独立 SVG；手册同时提供 Mermaid 源码，便于代码审查。

日常一致性检查：`.venv/bin/python scripts/acp_pipeline.py check --manifests`。检查通过表示路径与分类完整，不表示训练准入；数值查询超时等处理失败仍保留在质量报告中。
